## 1. أخطر ما وُجد — خرق المادة 21

نص المادة: حقل `critical` **«لا يوقف النواة إطلاقًا»**.

الكود كان يفعل العكس تمامًا. `Bootloader.boot()` كان فيه:

```python
if self._registry.get(atom_id).critical:
    self._abort_reason = f"فشلت ذرة حرجة أثناء التشغيل: {atom_id}"
    return BootReport(..., success=False)   # ← يخرج من الدالة
```

هذا `return` يحرم **كل ذرة تالية في ترتيب الإقلاع** من التشغيل. ذرة
حرجة واحدة تفشل ⇒ المنصة كلها لا تعمل. وكان `_resolve_with_graceful_degradation`
يُرجع `None` بنفس المنطق عند اعتمادية مفقودة لذرة حرجة.

المفارقة أن `run_core.py` كان يطبع بعدها: *«Core يستمر بالعمل كالمعتاد»* —
بينما الإقلاع قد أُجهض فعلًا.

**الآن**: الذرة الحرجة الفاشلة تُستبعد وحدها، ويكمل Core إقلاع الباقي،
و`success=False` صار يعني «فشلت ذرة حرجة» لا «توقف النظام».

**الإثبات**: `tests/core/test_article_21_critical_never_stops_core.py`
— ستة اختبارات، خمسة منها تسقط على الكود القديم.

## 2. المادة 89 — مشترك واحد يجمّد الناقل كله

`EventBus.publish` كان ينتظر كل المعالجات بلا مهلة:

```python
results = await asyncio.gather(*(self._invoke(sub, payload) for sub in subs), ...)
```

معالج واحد يعلّق (شبكة، قفل، حلقة لا نهائية) ⇒ الناشر ينتظر للأبد، وكل
مشترك آخر في نفس الحدث لا يستلم شيئًا. المادة 89 تمنع هذا صراحةً على
الذرة «البطيئة» لا التالفة فقط.

**الآن**: `asyncio.wait_for` لكل معالج على حدة (`dispatch_timeout_s`).
المعلّق يُعزل ويُسجَّل، والباقي يستلم أحداثه.

## 3. المادة 30/35 — المشتركون يتشاركون نفس القاموس

```python
payload = payload or {}
payload["trace_id"] = ...          # ← يعدّل قاموس المستدعي في مكانه
... self._invoke(sub, payload)     # ← نفس الكائن لكل المشتركين
```

نتيجتان: حمولة المستدعي تُلوَّث بحقول لم يضعها، وأي مشترك يعدّل الحمولة
يغيّر ما يراه المشتركون الذين بعده.

**الآن**: نسخة تُبنى قبل الحقن، وكل مشترك يستلم `dict(base)` مستقلة.

## 4. المادة 31 — المصدر لا يصل أبدًا

`publisher` كان يُسجَّل في اللوغ ثم يُرمى. المادة 31 تُلزم أن تحمل
الحمولة مصدرها. **الآن** `source` يُحقن مع `trace_id` و`timestamp`
بـ `setdefault` (فالذرة التي تضبطه بنفسها تحتفظ بقيمتها).

## 5. تسريب الموارد

| أين | ماذا كان يحدث |
|---|---|
| `_initialize_and_start` | نجح `initialize` وفشل `start` ⇒ لا `stop` ولا `shutdown` ⇒ ما فتحته الذرة يبقى مفتوحًا (المادة 16/85) |
| `_hot_load` | فشل التحميل الحي ⇒ الذرة تبقى في Registry بحالة `STARTING` إلى الأبد، والفحص التالي يراها «مسجَّلة» فلا يعيد المحاولة حتى بعد إصلاحها |
| `_hot_unload` | استثناء من `stop()` ⇒ لا `unregister` ولا `unsubscribe_all` ⇒ ذرة سيئة السلوك تترك أثرها للأبد (المادة 15) |
| `HealthManager._loop` | المهمة تنتهي وتبقى في `_tasks` ⇒ `watch()` يرفض إعادة مراقبة نفس الذرة |
| `Metrics._Timer.samples` | `list` تنمو بلا سقف مع كل قياس |
| `Journal._entries` | `list` تنمو بلا سقف مع كل إدخال |

**الآن**: تنظيف مضمون بـ `finally` في كل مسار، `deque(maxlen=…)` للنافذتين
(مع بقاء `count` و`avg_ms` دقيقين على كامل العمر، والقرص مصدرًا كاملاً
للحقيقة)، و`forget_atom()` لمحو أثر ذرة أُزيلت.

## 6. الاكتشاف الحي

- **`core_version` كان يُتجاهل تمامًا** عند التحميل الحي — ذرة غير
  متوافقة تمر من الباب الخلفي رغم أن Bootloader يرفضها (المادة 20).
- **`startup_mode` كان يُتجاهل** — ذرة معلنة `manual` تُشغَّل قسرًا.
- **ترتيب التحميل كان `sorted()` بالمعرّف الرقمي** — ذرتان جديدتان
  تصلان معًا وإحداهما تعتمد على الأخرى تُحمّلان بترتيب خاطئ.
- **لا قفل**: الفحص الدوري و`POST /api/rescan` قد ينطلقان معًا فيُسجَّل
  نفس الشيء مرتين.

## 7. متفرقات

| العيب | التصحيح |
|---|---|
| كتابة اللقطة `write_text` مباشرة | `tempfile` + `fsync` + `os.replace` ذرّي — انقطاع وسط الكتابة لم يعد يُتلف اللقطة السليمة |
| `snapshot()` بلا مهلة | ذرة معلّقة كانت تجمّد إيقاف Core كله |
| عدم توافق الإصدار يرفع `MissingDependencyError` | صار `VersionIncompatibleError` — رمزان مختلفان (2103/2101) |
| `bus.unsubscribe` على `defaultdict` | كان يُنشئ مفتاحًا وهميًا لحدث لم يُشترك فيه قط |
| `instantiate` لا يسجّل الموديول في `sys.modules` | يكسر `dataclasses` و`pickle` داخل كود الذرة |
| `/api/atoms/{id}/stop` لا يُلغي المراقبة | Health Manager كان قد يعيد تشغيل ذرة أوقفتها عمدًا |
| `record.state.value != "running"` | نص سحري بدل `AtomState.RUNNING` |
| اللقطة تُلتقط قبل إيقاف الاكتشاف الحي | صار الاكتشاف يتوقف أولًا |
| `AtomBase` مستورد بلا استخدام | حُذف (المادة 77) |
