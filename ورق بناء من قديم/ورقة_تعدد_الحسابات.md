# ورقة بنية — تعدّد الحسابات والمنصّات (Multi-Account)

**الحالة: مسجَّلة · لم تُنفَّذ**
**التاريخ: 2026-08-01**
**رُفعت بملاحظة المالك — والخطأ الذي تصحّحه خطأ Claude**

---

## الخطأ الذي تصحّحه هذه الورقة

**اقترحتُ حذف مخرَجات 651 بحجّة أن «الجميع يقرأ المصدر مباشرة».**

**والصحيح عكسه تمامًا: قراءة الجميع من المصدر مباشرة هي المشكلة، لا الحلّ.**

**واقتراحي كان يثبّت الربط بمنصّة واحدة بدل أن يفكّه.**

---

## القرار

**النظام يجب أن يدير أكثر من حساب على أكثر من منصّة في وقت واحد:**

```
MT5 حساب شخصي
MT5 حساب ممول
بايننس
ريثمك
نينجا تريدر — عقود آجلة
```

**وقسم المحافظ (650) هو الطبقة التي تعزل النظام عن المنصّة.**

---

## الحالة كما هي — بالقياس

### تسع ذرّات مربوطة بمنصّة واحدة مباشرة

```
platform.account.state  →  507 · 506 · 508 · 517 · 513 · 551 · 659 · 651 · 658
```

**كلّها تقرأ من 619 — قارئ جسر MT5.**

### ولا حقل يعرّف الحساب

```
account_id في أي إعداد   →  غير موجود
account_id في أي حمولة   →  غير موجود
```

**فالنظام كلّه يفترض حسابًا واحدًا على منصّة واحدة، ولا يقول ذلك في أي مكان.**

---

## ماذا يحدث عند إضافة مصدر ثانٍ

**افترض حسابًا ممولًا بجانب الشخصي:**

```
619   ينشر platform.account.state   ← الشخصي
619b  ينشر platform.account.state   ← الممول
```

**التسع ذرّات تسمع الاثنين وتخلطهما:**

| الذرّة | ما يحدث |
|---|---|
| **508** | يحسب انكشافًا على مجموع حسابين منفصلين |
| **516** | يوقف الاثنين لأن أحدهما بلغ حدّه |
| **551** | يحسب الحجم من حقوق حساب ويرسل الأمر إلى الآخر |
| **517** | يقيّد ربح حساب على استراتيجية نفّذت في الآخر |
| **506 · 507** | حدود جلسة وربح مخلوطة |
| **659 · 564** | يعلنان انحراف مراكز كاذبًا |

**وهذا ليس عطلًا يظهر في سجلّ: هو خلط صامت في الأرقام.**

**وأخطره 551 و508 — يمسّان حجم المركز والانكشاف بمال حقيقي.**

---

## البنية الصحيحة

**اليوم:**

```
619 (MT5)  ─────────────────→  تسع ذرّات
                                مربوطة بمنصّة واحدة
```

**المطلوب:**

```
619   MT5 شخصي     ─┐
619b  MT5 ممول     ─┤
6xx   بايننس       ─┼→  651 متتبّع الحسابات  →  portfolio.*  →  الجميع
6xx   ريثمك        ─┤      يعرف account_id
6xx   نينجا        ─┘      ويفصل بينها
```

**فـ651 يصير المصدر الوحيد لحالة الحساب، والتسع ذرّات تقرأ منه لا من الجسر.**

**وهذا هو غرض قسم المحافظ منذ البداية — طبقة تعزل النظام عن المنصّة.**

---

## ما يلزم — ستّة بنود

### ① `account_id` حقل إجباري

**في كل حمولة تمسّ حسابًا أو مركزًا أو أمرًا:**

```
platform.account.state     account_id
platform.positions.state   account_id
trade.opened · trade.closed account_id
execution.order.*          account_id
risk.*                     account_id
portfolio.*                account_id
```

**والقيمة تأتي من قارئ الجسر — فهو وحده يعرف أي حساب يقرأ.**

### ② 651 يتتبّع عدّة حسابات

**اليوم يحمل حالة واحدة. المطلوب `dict[account_id, state]`.**

```
651 ينشر:
   portfolio.account_tracked        لكل حساب على حدة
   portfolio.account_status_updated لكل حساب
   portfolio.accounts_summary       صورة موحّدة لكل الحسابات
```

**والتصنيف الذي يفعله اليوم — `classify(margin_level, margin)` — يبقى ويصير لكل حساب.**

### ③ التسع ذرّات تقرأ من 651

**تتوقّف عن الاشتراك بـ`platform.account.state` وتشترك بـ`portfolio.account_tracked`.**

**فتصير المنصّة غير مرئية لها — وهذا هو العزل.**

### ④ الحدود لكل حساب على حدة

| الذرّة | ما يتغيّر |
|---|---|
| **508** الانكشاف | سقف لكل حساب، لا مجموع |
| **516** المفتاح | يوقف الحساب الذي بلغ حدّه — أو الكل بقرار |
| **506** حدود الجلسة | لكل حساب |
| **507** حدود الربح | لكل حساب |
| **513** توزيع رأس المال | لكل حساب |

**وقرار مؤجّل: هل بلوغ حساب حدَّه يوقف بقيّة الحسابات؟**

### ⑤ 551 يعرف لأي حساب يبني

**الحجم يُحسب من حقوق الحساب المستهدف لا من أي حقوق.**

```
size = equity(account_id) × risk_pct / (stop_distance × contract_size)
```

### ⑥ 601 يكتب في جسر الحساب الصحيح

**اليوم قاعدة جسر واحدة. مع عدّة منصّات:**

```
MT5 شخصي    →  nq_brain.db  في Common\Files لهذا الطرفية
MT5 ممول    →  طرفية أخرى، قاعدة أخرى
بايننس      →  ليس SQLite أصلًا — واجهة برمجية
```

**فالجسر نفسه يصير متعدّدًا، لا القاعدة فقط.**

---

## ما لم يُحسم — وهو الأهم

| البند | السؤال |
|---|---|
| **الاستراتيجيات** | نسخة واحدة تخدم كل الحسابات، أم نسخة لكل حساب؟ |
| **القرار** | قرار واحد يُنفَّذ على عدّة حسابات، أم قرار لكل حساب؟ |
| **إيقاف حساب** | يوقف البقيّة أم يعزل نفسه؟ |
| **النماذج** | تتعلّم من كل الحسابات معًا أم كل حساب على حدة؟ |
| **الرموز** | `USTEC` في MT5 و`NAS100` عند وسيط آخر — و708 يوحّدها |
| **العملات** | حساب بالدولار وآخر باليورو — الربح لا يُجمَع مباشرة |
| **بايننس** | ليس جسر SQLite — يحتاج قارئ حساب من نوع مختلف |

## الأثر على ما بُني

**هذه الورقة تمسّ أكثر مما تبدو:**

```
تسع ذرّات تغيّر مصدرها
خمس ذرّات مخاطر تصير لكل حساب
551 يغيّر حساب الحجم
601 يصير متعدّد الجسور
708 يوحّد رموز عدّة وسطاء
650 · 651 يعاد بناؤهما
850 اللوحة تعرض حسابًا مختارًا أو الكل
```

**ولا تمسّ النواة.**

---

## علاقتها بالقرارات المعلّقة

**سؤال «652-657: تبقى مدمجة أم تُفصل؟» يتغيّر بهذه الورقة.**

**لم يعد السؤال «هل نفصل الحقول» — بل «كيف نفصل الحسابات».**

**فالقرار القديم مُعلَّق حتى تُحسم هذه الورقة.**

---

## الترتيب المقترَح

**هذه ورقة بنية لا إصلاح، وتُنفَّذ بعد أن يستقرّ الحساب الواحد:**

1. الإكسبرت يعمل وحساب واحد يتداول فعليًّا
2. أسبوع تشغيل يثبت أن السلسلة سليمة
3. **ثم** يُضاف `account_id` وتُفكّ التسع ذرّات
4. ثم يُضاف المصدر الثاني

**إضافة حساب ثانٍ قبل أن يعمل الأول تضاعف مساحة الخطأ بلا مكسب.**
